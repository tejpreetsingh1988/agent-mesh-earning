# ADR 042 — More verified metrics: net income, EBITDA, cash flow, cash

## Decision
Add seven metrics to the Critic-verified claims path
(growth claims via the generic Analyst loop, plus the
growth chart automatically):
- Net income (XBRL `NetIncomeLoss`, `ProfitLoss` alt).
- EBITDA, derived: operating income + D&A per period.
- Operating cash flow (`NetCashProvidedByUsedInOperatingActivities`).
- Free cash flow, derived: operating cash flow minus CapEx.
- Cash and equivalents (`CashAndCashEquivalentsAtCarryingValue`).
- Short-term investments (`ShortTermInvestments`).
- Cash + short-term investments, derived: the two balances summed.

## Mechanism
- Cash-flow items (D&A, OCF, CapEx) are YTD figures in
  10-Qs. `derive_discrete_ytd_rows(concept, metric)`
  (generalized from the D&A-only helper) differences
  consecutive fiscal periods within one `fy`, so fiscal
  calendars work; gaps yield no row, negative
  differences are skipped. Parsed discrete rows win
  dedupes. Q4 comes from the existing FY-minus-9M
  derivation, which already runs for every metric.
- Cash balances are instants, not flows: new
  `parse_instant_rows` (10-Q or 10-K, no start date,
  dedupe by period end, latest filed wins). A 10-K
  balance is the Q4 balance. Combined cash+ST only
  where BOTH exist per period — a cash-only sum would
  mislabel itself.
- CapEx XBRL values are positive payment amounts
  (verified live on MSFT: Q3 FY2026 discrete
  $30.876B), so FCF subtracts directly, no sign flip.
- D&A tags: `DepreciationDepletionAndAmortization`
  (DUK-style) and `Depreciation` (MSFT-style),
  recency-picked per company like revenue's alternates.

## Deliberately excluded from the XBRL path
Royalty and licensing revenue. The tags exist
(`RoyaltyRevenue` returns 200 for PFE) but PFE's rows
end in 2018 — the tag was abandoned. A stale royalty
fact would generate a stale YoY claim and trip the
Critic's per-claim staleness gate (claims citing only
facts >365 days before quarter_end FAIL), breaking
that company's briefing outright. Royalty/licensing
therefore live in the company-KPI layer (ADR 043),
where the source is the current quarter's release,
never a stale tag.

## Frontend
- Trend switcher gains Net income + EBITDA buttons;
  the old binary revenue/operating-income label
  ternary is now a label map. The switcher stays at
  4 buttons: `.chart-switch` is nowrap inline-flex,
  and 6+ buttons would overflow the rail card.
  OCF/FCF/cash appear in the claims table and the
  growth chart (both generic over growth claims).
- The TypeScript MCP port (`mcp-server/src/edgar.ts`)
  is a port of the old `edgar_facts.py` and does NOT
  have these tags yet — it needs the same additions
  when the MCP server goes live. It is not in the
  briefing path today, so this is drift to fix then,
  not now.

## Tests

(YTD differences incl. fiscal grouping, gap and
negative rules, OCF/FCF end-to-end, cash instants +
combined + both-required rule, Analyst claims).
One pre-existing test fixed: the companyfacts
fallback "fresh pick" fixture now also carries an
instant row, or the new balance metrics' empty picks
would correctly trigger the fallback. Full suite:
157 passed, 1 skipped.
